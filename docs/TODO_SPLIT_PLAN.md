# 큰 TODO 자동 나누기 — 계획 (2026-11-18)

구현은 아래 1~3단계 순서. **각 단계가 끝나면 멈추고 사용자 확인**을 받은 뒤 다음 단계로 간다.
11/17 밤의 "TODO Goal/Step/Milestone" 작업(되돌림, 마지막 커밋 `ce1e02a`)을 대신하는 가벼운 설계다.

## 0. 왜 다시, 왜 가볍게

- 목표(사용자): 2~3시간짜리 TODO 하나를 AI가 **처음부터 30분 안팎 조각으로 나눠** 보드에 넣고 차례로 한다.
  조각마다 전체 테스트를 돌리지 않고, **관련 테스트 + 커밋만** 하다가 **마무리 조각에서 전체 테스트 + push**.
- 지난번이 실패한 이유: 새 TODO 종류(Goal/Step/Milestone), Goal 전용 작업 폴더, 앱이 하는 합치기·검토·push 단계,
  자동 Fix Step, 새 push 거부 규칙을 한꺼번에(36커밋, 하룻밤, AI 둘이 번갈아) 만들었고, 중간에 기본 동작이 켜졌다.
- 이번 원칙
  - **보통 TODO를 그대로 쓴다.** 조각도 보통 TODO다. 새 상태(state)나 새 종류는 만들지 않는다.
  - 이미 있는 것 재사용: TODO 순서(`after`), 스케줄러, `task_done` 보고, 하위방의 작업 폴더(`SubWork`).
  - **스위치(기본 꺼짐)**: 설정 ▸ 채팅 ▸ "큰 TODO 자동 나누기 (실험)". 꺼져 있으면 지금과 똑같이 동작.
  - **한 AI가 맡는다** (작성 + 리뷰만 다른 AI). 단계마다 전체 test + build + HANDOFF 기록.

## 1. 동작 (사용자가 보는 것)

1. TODO를 시작하면, 스위치가 켜져 있고 일이 크다고 판단될 때 AI가 먼저 **나누기 계획**을 낸다.
   작으면(30분 안팎) 나누지 않고 지금처럼 한다.
2. 보드에서 원래 TODO 아래에 조각들이 순서대로 붙는다: `① … ② … ③ 마무리`. 원래 TODO는 **묶음 제목**이 되고
   "AI가 나눔 · 2/3" 처럼 진행이 보인다.
3. 조각은 차례로 자동 실행된다(앞 조각이 끝나야 다음). 중간 조각은 커밋까지만, **마무리 조각이 전체 테스트 후 push**.
4. 조각이 다 끝나면 묶음이 "확인 대기"가 되고, 사용자는 **묶음 하나만** 확인하면 된다.
5. 사용자는 언제든 묶음을 멈추기/취소할 수 있고, 남은 조각을 손으로 고칠 수 있다(지금 보드 기능 그대로).

## 2. 데이터 (todos.json, 필드 추가만)

`TodoItem`에 선택 필드 3개. 없으면 지금과 같은 보통 TODO.

| 필드 | 뜻 |
|---|---|
| `group: UUID?` | 조각이면 묶음 제목(원래 TODO)의 id |
| `piece: Piece?` | `.step`(중간: 관련 테스트 + 커밋, push 안 함) / `.finish`(마무리: 전체 테스트 + push) |
| `byAI: Bool?` | AI가 만든 조각 (보드 표시, AI가 고칠 수 있는 범위) |

- 묶음 제목은 상태를 따로 갖지 않고 **조각들의 상태로 계산**: 하나라도 진행 중이면 진행 중, 다 끝나면 확인 대기.
  (저장된 `state`는 나눈 순간 `running` 그대로 두고, 보드와 스케줄러는 계산값을 쓴다.)
- 조각 순서는 `after`로 잇는다: ②.after = [①], ③.after = [②]. 묶음 뒤의 다른 TODO가 묶음을 기다리던 연결은
  마무리 조각으로 옮긴다.
- 옛 앱이 새 필드를 모르는 파일을 읽어도 보통 TODO로 보이게(필드는 선택, 알 수 없는 값은 무시).

## 3. AI 도구와 권한

지금: `todo_add`/`todo_edit`는 "사용자가 시킬 때만", `todo_add`는 초안으로만. 이건 **그대로 둔다.**
새로 주는 권한은 **자기 묶음 안에서만**:

| 도구 | 누가 | 하는 일 | 제한 |
|---|---|---|---|
| `task_split(pieces)` | 실행 중인 TODO의 AI (스위치 켜짐, 그 TODO가 아직 조각이 아닐 때) | 자기 TODO를 2~6조각으로 나눔. 각 조각: title, detail(목표·할 일·끝 조건·건드릴 파일), `finish` 여부. 마지막 조각은 반드시 `finish` | 한 번만, 조각을 또 나누지 못함, 최대 6, 같은 프로젝트, 앱이 한 번에 저장(반쯤 저장 없음) |
| `task_pieces` | 조각을 맡은 AI | 같은 묶음 조각들의 상태와 **앞 조각들의 `task_done` 보고** 읽기 | 읽기만 |
| `task_piece_edit(id, …)` | 같은 묶음의 AI | **아직 시작 안 한** 조각의 title/detail 고치기, 취소, 순서 바꾸기, 조각 하나 끼워 넣기(예: 테스트 실패 고치기) | 자기 묶음만, 진행 중·끝난 조각 불가, 합계 6 이하, 마지막은 항상 `finish` |

막는 것
- 사용자가 만든 다른 TODO, 다른 묶음, 다른 프로젝트는 못 건드림 (앱이 `group`과 `byAI`로 검사).
- 스위치가 꺼져 있으면 `task_split`은 목록에 없음. 이미 만든 묶음은 끝까지 감(하위방 스위치와 같은 규칙).
- 완전 자동이 아니면 나누기 계획은 **승인 카드**(하위방과 같은 카드), 완전 자동이면 바로 저장하고 카드는 기록용.

## 4. 작업 폴더와 push

- 중간 조각은 push하지 않으므로, 커밋이 쌓이는 동안 **메인 폴더에서 다른 채팅이 push하면 섞인다.** 그래서 묶음 전용
  작업 폴더를 쓴다: 하위방의 `SubWork`(git worktree, 앱 데이터 폴더 아래, 브랜치 `todo/<묶음 id 앞 8자>`)를 재사용.
  - 첫 조각 시작 때 원격 대상 브랜치(main)에서 만든다. 모든 조각이 이 폴더에서 일한다.
  - 마무리 조각: 최신 main을 받아 합치고(충돌이면 그 조각이 고침) → **전체 테스트** → 앱이 main으로 push(fast-forward).
  - push가 성공하고 깨끗하면 폴더와 브랜치를 지운다. 실패·취소면 남기고 카드로 "이어하기/버리기".
- 새 push 거부 규칙은 만들지 않는다. 조각 브랜치(`todo/…`)는 push 허용 목록에 없으니 중간 조각은 원래 push할 수 없다.
- 문서 프로젝트·Git 없는 폴더는 작업 폴더 없이 지금처럼(나누기만 하고 조각마다 끝).

## 5. 테스트 규칙 (조각 안에서)

- 중간 조각: `--affected <바꾼 파일>`(관련 테스트) 통과 + 커밋 → `task_done`. 실패하면 그 조각에서 고친다.
- 마무리 조각: 전체 `test` + (있으면) `build`. 실패하면 마무리 조각이 고치거나 `task_piece_edit`로 고치기 조각을 끼움.
- 리뷰: 지금처럼 TODO마다 다른 AI 리뷰는 마무리 조각에서 **묶음 전체 변경(시작점…끝)** 을 한 번 본다.
  중간 조각은 리뷰 생략(사용량 절약). 스위치 꺼짐이면 지금 규칙 그대로.

## 6. 단계 (각 단계 끝에 멈춤)

1. **데이터 + 나누기 + 보드 표시** (작업 폴더 없음, push는 지금처럼 조각마다):
   필드 3개, `task_split`, 묶음 제목 계산, 보드의 묶음 표시·진행, 스위치, 승인 카드.
   → 확인: 실제 TODO 하나를 AI가 나누는지, 보드가 알아보기 쉬운지.
2. **조각 사이 이어받기**: `task_pieces`(앞 보고 읽기), `task_piece_edit`, 마지막 `finish` 규칙.
   → 확인: 조각 2가 조각 1의 결과를 알고 이어서 하는지.
3. **작업 폴더 + 마무리에서만 push**: `SubWork` 재사용, 중간 커밋만, 마무리에서 합치기·전체 테스트·push, 정리 카드.
   → 확인: 실제 프로젝트(AI Face 같은 작은 것)에서 3조각 묶음이 끝까지 가고 main에 한 번만 push되는지.

## 7. 테스트 (tools/tests, 가짜 AI + 임시 저장소)

- 1단계: 나누기 저장이 한 번에 됨, 6 초과·두 번 나누기·조각 재분할·finish 없는 계획 거부, 순서(`after`) 연결,
  묶음 상태 계산, 묶음 뒤 TODO의 연결 이동, 스위치 꺼짐이면 도구 없음, 옛 todos.json 읽기.
- 2단계: 앞 보고 읽기, 시작한 조각 수정 거부, 다른 묶음·사용자 TODO 수정 거부.
- 3단계: 중간 조각 push 없음, 마무리에서 main fast-forward push 한 번, 충돌 시 마무리가 받음, 실패 시 폴더 남김.
- 매 단계 전체 `zsh tools/tests/run_mode2.sh`, `zsh tools/build_app.sh --stage < /dev/null`, `python3 tools/tests/check_signing.py`.

## 8. 하지 않는 것

- 새 TODO 종류(Goal/Step/Milestone), 앱이 따로 돌리는 Milestone 단계, 자동 Fix Step, 새 push 거부 규칙.
- 폰 원격 업데이트, 설치·서명 파일 변경.
- 스위치를 기본 켜짐으로 바꾸는 것(사용자가 정함).
