## 0. 왜 다시, 왜 가볍게

- 목표(사용자): 2~3시간짜리 TODO 하나를 AI가 **처음부터 30분 안팎 조각으로 나눠** 보드에 넣고 차례로 한다.
  조각마다 전체 테스트를 돌리지 않고, **관련 테스트 + 커밋만** 하다가 **마무리 조각에서 전체 테스트 + push**.
- 지난번이 실패한 이유: 새 TODO 종류, Goal 전용 작업 폴더, 앱이 하는 합치기·검토·push 단계, 자동 Fix Step,
  새 push 거부 규칙을 한꺼번에(하룻밤, AI 둘이 번갈아) 만들었고, 중간에 기본 동작이 켜졌다.
- 원칙
  - **보통 TODO를 그대로 쓴다.** 조각도 보통 TODO다. 새 상태(state)나 새 종류는 만들지 않는다.
  - 재사용: TODO 순서(`after`), 스케줄러, `task_done` 보고, 하위방의 push 막기(`isSubRoom` 방식).
  - **스위치(기본 꺼짐)**: 설정 ▸ 채팅 ▸ "큰 TODO 자동 나누기 (실험)". 꺼져 있으면 지금과 똑같이 동작.
  - **한 AI가 맡는다** (작성 + 리뷰만 다른 AI). 단계마다 전체 test + build + HANDOFF 기록.

## 1.5 확정 규칙 (애매했던 부분, 2026-11-18)

**언제 나누기를 제안하나** (스위치가 켜져 있을 때만)
- 사용자가 TODO에 "나눠서"라고 썼으면 항상 제안.
- 아니면 AI가 첫 실행에서 파일을 바꾸기 전에 코드를 읽고, 아래 둘 다일 때만 제안: 예상 60분 이상, **그리고**
  순서대로 해야 하는 부분이 2개 이상(앞 결과가 있어야 뒤를 할 수 있음). 둘 중 하나라도 아니면 나누지 않는다.
- 완전 자동(`workspace.isFullAuto`)이면 승인 카드 없이 바로 나누고 실행한다. 하위방이 완전 자동에서 바로 승인되는 것과 같다(`Delegate.swift`의 `delegateNote`). 다른 모드에서는 나누기 카드를 띄운다.
- 예상 시간, 그렇게 본 이유 한 줄, 조각마다 바꿀 파일은 카드에 보인다. 완전 자동에서는 보드의 마무리 줄과 마무리 보고에 같은 내용을 기록한다.

**어디를 나누나**
- 조각 하나가 끝나면 앱이 **빌드되고 관련 테스트가 통과**해야 한다. 그렇게 못 끊으면 그 지점에서 나누지 않는다.
- 조각마다 "끝 조건" 한 줄(어떤 테스트가 통과하면 끝인지)을 적는다. 끝 조건이 없는 조각은 만들 수 없다.
- 순서는 보통 저장 형식 → 동작 → 화면. 조각 2~6개(마무리 포함), 하나에 30분 안팎.

**나누기와 하위방**
- TODO 하나에는 둘 중 하나만. 판단 순서: 나누기를 먼저(파일 바꾸기 전) 본다. 나누면 묶음의 모든 조각에서
  하위방 도구를 뺀다(`noPush`처럼 목록에서 빼고 직접 불러도 거부). 거절했거나 안 나눴으면 지금처럼 하위방을 쓸 수 있다.
- 함께 쓰는 것은 하위방 P4와 이 기능 3단계가 끝난 뒤에 다시 정한다.

**조각이 생각보다 클 때**: 1단계에서는 그 조각을 끝까지 한다(다시 나누기 없음). 2단계부터 `task_piece_edit`로 끼워 넣기.

**8절 결정**: 사용자가 "진행"을 정했으므로 회의 추천대로 확정한다(1 예, 2 실제 실행, 3 받아들이고 표시 + 시험은 AI Face,
4 60분 또는 "나눠서", 5 중간 리뷰 생략, 6 완전 자동이면 카드 생략).

**조각이 막혔을 때**: 끝 조건의 테스트 실패를 고치지 못하면 그 조각만 `needsYou`로 둔다. 뒤 조각과 마무리는 시작하지 않는다.

**1단계를 TODO 4개로**: 각 TODO가 끝날 때마다 push되므로 스위치는 4번에만 넣는다. 그 전에는 켤 방법이 없어 앱 동작이 그대로다.
1. 저장 형식: 3절 필드, `TodoStore.split`(한 번에 저장, 원래 TODO 바로 위에 넣기), 옛 파일 읽기. 7절 테스트 4·8(저장 부분)·9.
2. 실행 규칙: `noPush`·하위방 도구 빼기, 중간 `.done`/마무리 `.review`, 늦은 `task_done` 무시, 취소 우회 막기. 7절 1·2·3·5·6·7·11.
3. AI 도구: `task_split`(1.5의 카드 내용 포함), `task_pieces`. 7절 8(도구 부분)·10.
   구현(2026-11-18): 스위치 키 `todoSplitEnabled`(`TaskLink.splitEnabled`, 기본 꺼짐, 화면은 4). "첫 실행"은 처음 running이 된 그 실행
   (`startedAt == stateSince`), "파일 바꾸기 전"은 그 실행에서 커밋 없음 + HEAD가 시작 커밋 그대로 + 처음에 없던 변경 파일 없음.
   승인 카드는 일반 승인 카드(`ProjectApproval`), 거절이나 15분 무응답이면 `splitDeclined`. 마무리의 끝 조건은 카드에만 보이고 저장하지 않는다.
4. 화면: 보드 표시, 승인 카드, 스위치(기본 꺼짐). AI Face에서 실제 TODO 하나로 시험.

## 2. 동작 (사용자가 보는 것)

1. TODO를 시작하면, 스위치가 켜져 있고 일이 크다고 판단될 때 AI가 먼저 **나누기 계획**을 낸다.
   기준: 예상 60분 이상이거나 사용자가 "나눠서"라고 썼을 때(사용자 결정 4). 조각은 30분 안팎, 2~6개.
2. 완전 자동(`workspace.isFullAuto`)이면 하위방과 같이 승인 카드 없이 바로 나누고 실행한다. 예상 시간, 이유 한 줄,
   조각별 파일은 보드의 마무리 줄과 마무리 보고에 남긴다. 다른 모드에서는 승인 카드로 묻고, 거절하면 원래대로 진행한다.
3. 보드: 원래 TODO 위에 ①②가 붙고, 원래 TODO 줄은 "마무리 · AI가 나눔 · 1/3"처럼 진행을 보인다.
4. 조각은 차례로 자동 실행. 중간 조각은 관련 테스트 + 커밋까지, **마무리가 전체 테스트 + 리뷰 + push 한 번**.
5. 사용자는 **마무리 하나만** 확인한다. 언제든 묶음을 멈추기/취소, 아직 시작 안 한 조각을 손으로 고칠 수 있다.

## 3. 데이터 (todos.json, 필드 추가만)

`TodoItem`에 선택 필드(`decodeIfPresent`). 없으면 지금과 같은 보통 TODO.

| 필드 | 뜻 |
|---|---|
| `group: UUID?` | 조각이면 묶음 id(= 원래 TODO = 마무리의 id). 마무리 자신도 자기 id |
| `piece: Piece?` | `.step`(중간) / `.finish`(마무리, 묶음에 정확히 하나, 항상 마지막) |
| `byAI: Bool?` | AI가 새로 작성한 중간 조각 (보드 표시, AI가 고칠 수 있는 범위). 마무리는 원래 TODO의 값을 유지 |
| `splitDeclined: Bool?` | 나누기 카드를 거절함 → 다시 제안 안 함 |
| `splitRecord: SplitRecord?` | 마무리 줄에 저장하는 예상 시간(분), 이유 한 줄, 조각 ID와 파일 경로 목록(보드 순서, 마무리 포함) |

- `TodoStore.split`이 한 번에 저장(반쯤 저장 없음). 순서: ①.after = 원래 after, ②.after = [①], 마무리.after = [마지막 ②].
- 보드 순서(`list.order`)에서 ①②는 **원래 TODO 바로 위**에 넣는다(`place(_, before: 원래)`). 그 아래 ready TODO는 지금처럼
  바로 위 TODO(= 마무리)를 기다리므로 묶음 전체가 끝난 뒤 시작한다. 맨 뒤에 붙이면 ①이 아래 TODO를 기다리고 그 TODO는
  마무리를 기다려 서로 기다리는 원이 생긴다(`hasCycle`).
- 마무리는 원래 TODO의 메모, 시간 기록, 첨부, 시작 전 질문 설정(`askFirst`)을 보존하고 시도 상태를 초기화한다.
  중간 조각은 실행할 때 원래 TODO의 첨부를 복사해 받는다. 시작 전 질문 설정은 원래 실행과 마무리에 적용한다. 마무리에서는 기존 답변을 사용하고 해결되지 않은 질문만 한다.
  작업 계정은 목록 설정에서 실행마다 정한다. 나누기 전 실행이 시작한 커밋을 마무리의 `splitRecord.reviewBase`에 저장한다. 이 값이 없는 묶음은 첫 조각이 시작할 때 기록한다.
- 옛 앱이 읽어도 보통 TODO 몇 개로 보인다(마무리가 ②를 기다리므로 순서도 지켜짐).

## 4. AI 도구와 권한

`todo_add`/`todo_edit`의 지금 규칙("사용자가 시킬 때만", 초안만)은 **그대로**. 새 권한은 **자기 묶음 안에서만**:

| 도구 | 누가 | 하는 일 | 제한 |
|---|---|---|---|
| `task_split(pieces)` | 실행 중인 TODO의 AI (스위치 켜짐, 조각 아님, 파일 바꾸기 전, 거절 이력 없음) | 앞 조각 1~5개 + 원래 TODO를 마무리로 | 한 번만, 조각 재분할 불가, 합계 6 이하, 같은 프로젝트 |
| `task_pieces` | 조각을 맡은 AI | 같은 묶음 조각들의 상태와 **앞 조각들의 `task_done` 보고** 읽기 | 읽기만 |
| `task_piece_edit(id, …)` | 같은 묶음의 AI | **아직 시작 안 한** 조각 title/detail 고치기, 취소, 순서, 끼워 넣기(예: 테스트 고치기) | 자기 묶음만, 진행 중·끝난 조각 불가, 합계 6 이하, 마무리는 항상 마지막 |

- 다른 TODO·묶음·프로젝트는 못 건드림(`group`·`byAI`로 검사). 스위치 꺼짐이면 `task_split`은 목록에 없음. 이미 만든 묶음은 끝까지 감.

## 5. 테스트 규칙 (조각 안에서)

- 중간 조각: `--affected <바꾼 파일>` 통과 + 커밋 → `task_done`. 실패하면 그 조각에서 고친다. 다른 AI 리뷰 생략(사용자 결정 5).
- 마무리: 전체 `test` + (있으면) `build` + 묶음 전체 변경(① 이전…끝) 리뷰 → push. 실패하면 고치거나 `task_piece_edit`로 고치기 조각을 끼움.

## 6. 단계 (각 단계 끝에 멈춤)

1. **나누기 + 순차 실행 + 마무리에서만 push** (첫 안의 1·2단계 합침. `task_pieces` 없이는 ②가 ①을 몰라서 써 볼 수 없음):
   필드, `TodoStore.split`, `task_split`, `task_pieces`, `noPush`, 중간 `.done`/마무리 `.review`, 늦은 `task_done` 무시,
   취소 우회 막기, 보드 표시, 스위치, 승인 카드.
   - 한계: 조각 사이에 같은 프로젝트의 **다른 채팅**이 push하면 아직 검증 안 된 조각 커밋도 같이 나간다.
     보드에 "push 안 된 조각 커밋 n개"를 보이고, 실제 Git 프로젝트에서 쓸지는 사용자 결정 3.
   → 확인: 실제 TODO 하나가 ①→②→마무리로 가고, push가 한 번인지.
2. **`task_piece_edit`** (시작 안 한 조각 고치기·끼우기·취소).
3. **묶음 작업 폴더**(위 한계 해소): 하위방 P4 통과 후, SubWork를 `todo/<id 8자>` 브랜치·원격 main 기준·마무리 fast-forward push로 넓히는 설계부터.

## 7. 테스트 (tools/tests, 가짜 AI + 임시 저장소)

1단계:
1. 나누기 직전에 `live()`를 통과한 `task_done`이 저장 뒤에 와도 무시됨
2. `checkEach`에서 중간 카드 없이 마무리까지 감
3. ②를 취소한 뒤 답변·위임을 해도 마무리가 시작 안 됨
4. 나눈 직후 `recover()`해도 원래 TODO가 다시 실행 안 됨
5. ①→②→마무리 순서
6. `noPush`면 `git_push`가 목록에 없고 직접 불러도 거부
7. 가짜 원격에서 push 한 번, 마지막 SHA 일치
8. 거부: 6개 초과, 두 번 나누기, 조각 재분할, 파일 바꾼 뒤 나누기, 거절 뒤 다시 제안, `.finish` 중복·누락
9. 스위치 꺼짐이면 도구 없음, 옛 todos.json 읽기, 새 파일을 옛 형식으로 읽어도 순서 유지
10. 완전 자동이면 카드 없이 바로 나누고 실행함
11. 조각이 `needsYou`이면 뒤 조각과 마무리가 시작하지 않음

2단계: 시작한 조각 수정 거부, 다른 묶음·사용자 TODO 수정 거부. 3단계: 충돌 시 마무리가 받음, 실패 시 폴더 남김.
매 단계 전체 `zsh tools/tests/run_mode2.sh`, `zsh tools/build_app.sh --stage < /dev/null`, `python3 tools/tests/check_signing.py`.

## 8. 사용자가 정할 것 (괄호 = 회의 추천)

1. 원래 TODO를 마무리로 쓰기 — 보드에 따로 묶음 제목 줄이 없고 마지막 줄이 원래 제목 (추천: 예)
2. 첫 단계를 실제 순차 실행으로 (추천: 예. ChatGPT는 실행 없는 미리보기를 먼저 하자는 입장)
3. 1단계 한계(다른 채팅의 push에 조각 커밋이 섞임)를 받아들이고 실제 Git 프로젝트에서 켤지 (추천: 받아들이고 표시, 시험은 AI Face 같은 작은 프로젝트)
4. 나누기 기준 60분 / 30분 (추천: 60분 또는 "나눠서" 요청)
5. 중간 조각 다른 AI 리뷰 생략 (추천: 생략, 마무리에서 전체 한 번)
6. 결정됨: 완전 자동이면 카드 생략

## 9. 하지 않는 것

- 새 TODO 종류(Goal/Step/Milestone), 앱이 따로 돌리는 Milestone 단계, 자동 Fix Step, 새 push 거부 규칙.
- 폰 원격 업데이트, 설치·서명 파일 변경.
- 스위치를 기본 켜짐으로 바꾸는 것(사용자가 정함).
